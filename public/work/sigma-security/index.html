01 / Context

A team model needs a usable interface.

SigmaSecurity was a four-member project for COS30049 at Swinburne, exploring machine-learning-assisted spam and malware detection. The team combined a React interface with Python/FastAPI services and machine-learning work.

My contribution centred on frontend engineering and UX/UI. The reviewed browser workflow accepts text and requests a classification from the team’s spam-detection endpoint.

02 / My contribution

From the first layout to the result screen.

Build the application structure

I started with an HTML/CSS prototype, set up the React application, and developed reusable header, sidebar and footer components. I worked on routing between Home, Dashboard and About, plus styling and light/dark theme behaviour.

Connect the text-scanning flow

I developed and refined the scanner input, example cases, Axios API requests and result presentation. Frontend error handling and an ErrorBoundary helped the application account for failures as well as successful responses.

Make the dashboard understandable

I built and iterated on Chart.js visualisations, KPI cards and dashboard layouts. These use demonstration values in the reviewed source, so they illustrate the interface rather than live security monitoring.

Project status: Academic prototype. Backend services and machine-learning models were team contributions, not my individual work. No model-accuracy or production-deployment claim is made here.

04 / Reflection

The interface is part of the system.

This project connected my frontend work to a service built by other people. I had to consider the request format, returned data, navigation and failure states together, rather than treating each screen as an isolated layout.

It also taught me to distinguish a visual prototype from a validated system. A dashboard can communicate an idea clearly while its values are still illustrative; that boundary needs to remain visible.
