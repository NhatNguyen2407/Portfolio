01 / Context

A small product world.
A connected customer journey.

Dioxyzine Frog is an e-commerce project for custom plushies, dolls, and accessories. The application brings together product discovery, inquiries, customer accounts, checkout, and order tracking.

My work has been to develop and maintain those journeys while learning how the frontend connects to authentication, database rules, payment services, and deployment.

02 / My contribution

Working across the experience.

I work across the React interface and its backend integrations, using AI-assisted development as part of the process. The repository began with a Figma-origin code bundle; my contribution includes extending features, connecting services, debugging, and reviewing changes through GitHub.

  1. DiscoverProduct browsing, product details, custom inquiries, and wishlist.
  2. ChooseCart and checkout interactions, including PayPal Sandbox integration.
  3. Follow throughCustomer profile, order history, and tracking flows.
  4. MaintainAdministrative features, environment configuration, and release fixes.

03 / Engineering decisions

The work behind the visible page.

Keep order logic behind the interface

A checkout interface is only one part of an order. The project connects the React application to Supabase services and server-side payment handling, with PayPal Sandbox used for development and testing.

Make access boundaries explicit

The security-hardening work addresses row-level security, storage writes, and database function permissions. It also narrows the information exposed through public order tracking.

Integrate changes as a release

Pre-launch work brought together profile settings, wishlist improvements, responsive and accessibility fixes, and payment compatibility changes. GitHub pull requests make that integration work visible.

Current boundary: PayPal remains in Sandbox. This case study demonstrates implementation and testing work; it does not claim live-payment readiness or commercial results.

05 / Reflection

A useful interface needs a reliable foundation.

This project has pushed my learning beyond individual components. A change to checkout can involve application state, database access, environment variables, and deployment configuration at the same time.

It has also made me more deliberate about describing project status: what is implemented, what has been tested, and what still needs validation. That distinction matters as much as the polish of the page.
