01 / Context

Two sides of a residential community.

Digi-Capitale is a residential services management application with separate experiences for residents and employees. The shared codebase includes utility bookings, bills, incident reporting, and request management.

The frontend uses React and Material UI, with PHP and MySQL on the backend. My role was as a contributor to this larger team project.

02 / My contribution

Help people get to the right service.

Search, pagination, and multi-select filters

I contributed functionality for narrowing the utility list and moving between result pages. These changes work together to make a growing set of services easier to browse.

Time and date filters, with service cards

I worked on service-page presentation and filtering controls. The relevant development commit used dummy data, so it is evidence of interface implementation rather than measured real-world usage.

Booking state in the database

I also contributed a MySQL stored procedure for booking control. It uses transactions when approving, rejecting, or cancelling slots, connecting interface actions to changes in stored booking state.

04 / Reflection

A feature has to fit the whole system.

Working in a shared codebase means thinking beyond the component in front of me. Filters need to agree with the data shape, service cards need to fit established UI patterns, and booking actions need a consistent meaning in the database.

This project gave me experience contributing to an existing structure and making specific, reviewable changes alongside other people.

Scope: The application is team-built. The contributions above are linked to my authored commits; broader platform features are described as team context.
